# 編輯操作說明（EmDash 後台）

後台網址：`https://www.bigxreality.com/_emdash/admin`（用公司 email 登入）。

## 角色

| 角色 | 可以做的事 |
|---|---|
| 撰稿（Contributor） | 新增、編輯自己的草稿，不能發布 |
| 作者（Author） | 編輯自己的內容；**要等編輯核准後才能發布** |
| 編輯（Editor） | 編輯所有內容、核准、發布、下架 |
| 管理員（Admin） | 加上帳號、外掛與網站設定 |

## 發文流程
1. 新增內容，先寫**繁體中文**版（翻譯來源）。
2. 寫完把「審核狀態」改成 `submitted`（送審）。
3. 編輯檢查後改成 `approved`，或改成 `changes_requested`（請修改）。
4. 按「發布」。約 2 分鐘後網站會自動更新；連續發布多篇只會更新一次，最多延後 10 分鐘。

注意：
- 作者自己把狀態改成 `approved` 的話，存檔時會自動變回 `submitted`。
- 已核准的內容被作者修改後，也要重新送審。

## 翻譯
- 在中文內容右側選「翻譯」，建立 English／日本語 版本。
- 「翻譯狀態」選 `pending` 時，該語言頁面會顯示「[待翻譯]」橫幅，而且不會被搜尋引擎收錄。確認譯文後改成 `translated`。
- 網址代稱（slug）一律使用中文版的代稱，翻譯版填什麼都不影響網址。

## 各類內容的注意事項
- **消息**：選類型；展覽填活動名稱與日期，媒體報導填媒體名稱與網址。
- **技術文章**：可填作者，閱讀時間會自動計算。
- **成功案例**（後台「案例」集合；網站網址 `/tw/cases/`，主選單「成功案例」）：
  - 新增案例：後台 → 案例 → 新增。每個案例只建立一次，產品頁、解決方案頁與案例列表都由關聯資料自動讀取，**不需要改任何頁面或選單**。
  - 填寫順序：案例名稱、案例摘要、代表圖片（16:9）、導入單位名稱、單位類型、揭露方式、應用領域（軍事／警察／消防／智慧城市／其他，可複選）。
  - 內容區塊（專案背景、面臨的訓練挑戰、導入解決方案、實際應用方式、專案成果與效益、現場影像）：沒有資料的欄位留空，網站不會顯示該區塊與標題。段落之間空一行。
  - **客戶名稱的公開權限**：揭露方式選「public」才會顯示導入單位名稱；選「anonymized」只會顯示「單位類型」（例如「陸軍訓練單位」），所以未確認可公開的客戶請選 anonymized，並填單位類型。
  - **必須勾選「已取得客戶公開授權」**才會上線（任何角色都一樣）；未勾選、草稿或未發布的案例不會出現在案例列表、篩選、產品頁、解決方案頁或「延伸閱讀」。
  - **成果只填已確認、可公開的內容**：「專案成果與效益」寫敘述，「專案成果數據」填項目與數值；兩者都沒有就整個成果區塊隱藏。不要把參展、產品展示或媒體參訪當成導入案例。
  - 關聯：在案例上選「相關產品」「相關解決方案」（可複選）。產品頁會自動在「導入價值」之後顯示「實際應用案例」（1 個案例為橫向圖文，2 個以上為卡片，最多 3 個並提供「查看更多成功案例」），沒有案例就整塊隱藏；案例頁與案例列表也會自動連回產品與解決方案。
  - 案例列表的篩選（應用領域、關聯產品、關聯解決方案）只會列出已發布案例實際用到的項目。
  - 英文、日文版：先建立中文版，翻譯版另建同代稱的條目；翻譯狀態 `pending` 的頁面不會被搜尋引擎收錄。
- **標籤**：只能從「標籤」清單中選。新標籤請先在「標籤」新增並發布。少於 3 篇文章的標籤頁不會被搜尋引擎收錄。
- **關聯**（相關產品、解決方案、文章）只需要在一邊設定，另一邊會自動顯示。
- 正文空白的文章不會出現在網站上。
- 不知道的資料請填 `[待提供]`，網站上會以黃框標示。

## 圖片
- 上傳到「媒體庫」，每張圖都要填替代文字（alt）。
- 網站會自動產生各種尺寸與格式。

## 下架與還原
- 「取消發布」：網站上移除，內容保留為草稿。
- 「刪除」會先移到垃圾桶，可以還原。
- 每次儲存都有版本紀錄，可以比較差異、還原到舊版本。
